## Pre-production notes — read before scripting screen recording

- **This is longer than Tutorials' usual 2–4 minute target.** It's intentional: the brief for this video was to cover every one of the 18 toolbar buttons plus the Process/Send modes, the right-click menu, and Queue Settings — that's a reference-style walkthrough, not a single-task tutorial. Recommend publishing with YouTube chapter markers (timestamps in the description) so viewers can jump straight to the one control they're looking for, rather than expecting anyone to watch start to finish. If review decides this is still too long, the cleanest split is: **Part 1 — Process/Send modes** (through 2:30) as its own short video, **Part 2 — Toolbar reference + Queue Settings** (2:30 onward) as a second. Flagging this as a decision for review, not deciding it here.
- **"Process and Send Simultaneously" — needs SME clarification before this is treated as final.** The task brief asked for this as a named mode. The source support article does **not** use that phrase. It describes three Process/Send variations: *Process Only* (prepares the job without sending), *Process and Send* (sends to the printer, with copy-quantity options), and *Send* (transmits an already-processed job, optionally redirecting to a file). Two readings are possible:
  1. "Process and Send Simultaneously" is just plain-language for **Process and Send** — processing and sending happen as one combined action instead of two separate steps (Process Only, then Send later). This script treats it this way in the narration (Scene 3), and says so explicitly on screen so nobody mistakes it for a fourth mode.
  2. It could instead mean something more specific: the queue processing *one* job while simultaneously sending an already-processed *other* job to the printer — i.e., overlapping the RIP/processing stage on one job with the print/transmission stage on another, so the printer never sits idle waiting on the next file. This is a plausible thing for a production queue to do, but **the source article doesn't describe it**, and this script does not claim it happens — that would be inventing UI behavior. If this pipeline-overlap behavior is real, it needs an SME or support confirmation and, ideally, a screen recording that actually shows two jobs at different stages simultaneously (one "Processing," one "Printing") in the queue list — that's the only way to demonstrate it honestly. Flag this to Sales/Support before shooting; if confirmed, Scene 3 gets a short addendum. If not confirmed, keep the script as written (reading #1 only).
- **Do not fabricate exact on-screen button labels, icon glyphs, or dialog field names.** The source article names each button's *function* but not always its precise tooltip text or icon. Every visual cell below is written to describe what the recording should capture, not to assert exact label wording — screen-record against a live queue window and use the real on-screen text for lower-thirds/captions, don't retype from memory.
- **Screen recording needed, all live:** the queue window with several jobs in mixed states (waiting, processing, printing, paused, error, finished) so status differences are visible; the Process/Send flyout/dialog for all three modes; the right-click context menu; the Queue Settings dialog; and, if available, the cost calculation utility and the Advanced Options (Length Mode, Bi-directional Print, Cut Sheet at the End, Origin Setup) screens.
- No performance numbers or made-up job names in this script. If a demo queue is recorded, use placeholder job names (`Job_001.prn`, `SampleFile.plt`) — no real customer file names or paths.
- Confirm final CTA link before this leaves draft (same open item as the intro script — trial vs. demo vs. support article).
